# Jev Design

Jev answers atomic, versioned questions when the answer space is known. OntoCodex proposes
and synthesizes; Jev selects, scores, gates, ranks, or abstains; Python computes and executes.

`RESEARCH_CONTROL` judgments may rank gaps, acquisitions, methods, or bounded next moves. They
are never biological evidence. `SCIENTIFIC_EVALUATION` includes Wide, Deep, and future
hypothesis critique and remains distinct from deterministic measurement.

Consequential contracts identify role, purpose, input projection, question version, primitive,
outputs, baseline, evaluation status, failure behavior, and model version. Their lifecycle is
`PROPOSED → EVALUATED → ACCEPTED | REJECTED → VERSIONED`.

Bootstrap and offline evaluators are deterministic adapters behind these interfaces. In an adopted
observational program, Wide gates only complete scope-compatible descriptive evidence and Deep asks
for the registered independent-cohort follow-up before finalization. Passing software tests does
not scientifically validate or promote a Jev contract; model-backed Jev still requires separate
contract evaluation and human acceptance.

The opt-in TypeSafe adapter batches two Wide Choice questions over a bounded StatisticalState and
uses one Deep Choice over a bounded EvidenceState. It exposes explicit `ADMIT`, `DEFER`, `REJECT`,
and `ABSTAIN` Wide outcomes and only state-compatible Deep moves. API probabilities become judgment
scores, never evidence. Python admission and Stage 8 policies can reject or defer model selections.
